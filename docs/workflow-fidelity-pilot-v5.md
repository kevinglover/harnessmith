## Regression plan

| Failure family | Positive controls | Negative controls |
| --- | --- | --- |
| Internal Python append | Literal append, complete internal readback/assertion, exact prefix and final bytes | Dynamic or wrong target, missing verification, partial output, changed prefix, failed/denied operation |
| Compound read evidence | Exact pinned guidance/configuration returned before a later failure | Missing/truncated content, skipped reads, unsupported fallback chains; retain failed envelope |
| Final count | Completed singular/plural count descriptions | Wrong or conflicting counts, negation, plans and numbers inside paths |
| Hook selection/timing | Configured blocks after config read and before their phase actions | Invented IDs, extra blocks, late pre offers, promises and unselected execution |
| Error narration | Earlier matching returned command evidence | Unrecorded or later error, unsent delta, quoted/hypothetical/negated text used as evidence |
| Local workflow | Hidden-path discovery, shell setup and independent constitution read | Missing/empty directories, wrong interpreter and fallback-masked context loss |
| Collector integration | Fixed two synthetic results, pinned versions and durable artifacts | Unsupported claims and failed actions retained; instrumentation defects stop without retry |

All controls are newly constructed synthetic fixtures. No historical observation
is passed to a new checker or assigned a new grade. No real project hook runs.
Offline tests establish instrument/package behavior, not future model fidelity
or sandbox guarantees.
