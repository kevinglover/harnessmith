# P1 implementation follow-up — October 22, 2026

OPT-001, OPT-002, and OPT-003 are implemented and validated offline on
`codex/p1-portability`, branched from `main` at baseline `c5fa9d4`. This is an implementation follow-up,
not a replacement weekly review. The original measurements are unchanged.

| Opportunity | Result | Regression coverage |
| --- | --- | --- |

## Validation

- 104 unit/regression tests pass on Python 3.9.6, including all three offline
  evaluation scenarios and the pinned fixture target matrix.
- Coverage is 80%, above the repository's 75% gate.
- Ruff, mypy, schema validation, documentation links, and byte compilation pass.
  Emitted capability v2 documents pass the new schema and are rejected by v1.
- Existing and freshly generated Cursor examples pass all eight independent
  verifier categories. Regeneration produces no file differences.
- The 12-skill/four-target audit matrix completes: all 48 remain compatible with
  metadata/adapter policy, while the new body findings expose portability review
  needs. Compatibility does not assert runtime behavior.
- Source distribution and wheel build, Twine metadata checks, and an isolated
  wheel import/CLI smoke check are performed using temporary environments.

[Evidence](2026-10-22-p1-evidence.json) records source hashes, the audit matrix,
and emitted capabilities. The repository's optional development dependencies
were installed into a temporary virtual environment; the compiler retains zero
runtime dependencies. Bytecode caches and distribution outputs use temporary
paths. No package was published.

## Explicit limits

Runtime enforcement remains unverified. No live models or harnesses were run.
Body diagnostics are advisory and cover recognized syntax in the root body;
unknown syntax and external reference contents are outside the scanner's scope.
Markdown context is not proof that a host skips preprocessing. The metadata
interpreter deliberately rejects YAML forms outside its documented subset.
No canonical skill text or extraction recipe was rewritten. P2/P3 opportunities
remain proposed.

## Reproduction

Use a temporary environment containing the declared development dependencies:

```bash
python -m unittest discover -s tests -q
python -m coverage run -m unittest discover -s tests
python -m coverage report
python -m ruff check .
python -m mypy
python scripts/check_repository.py all
python -m compileall -q harnessmith tests scripts
python -m build --outdir /tmp/harnessmith-p1-dist
python -m twine check /tmp/harnessmith-p1-dist/*
```

Compile and independently verify the existing Cursor recipe as described in the
[baseline reproduction](2026-10-22.md#reproduction), then compare its generated
files with `examples/compiled/cursor/speckit-analyze`.
