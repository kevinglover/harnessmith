normal-path instruction context by 21%. This validates an existing static result,
not model quality, latency, cost, or actual token savings.

### Reproducible audit gaps

Temporary probe inputs were audited against all four targets. Each returned
`target_compatible: true` and an empty `warnings` list:

1. A skill with name `BAD--NAME` and a 1,025-character description. Both violate
   standard constraints. This is a confirmed standard-validation gap.
2. A skill body containing Claude dynamic-command notation and argument/skill
   directory substitutions. These were accepted for non-Claude targets without
   identifying the host-dependent behavior. This demonstrates missing diagnostics;
   it does not prove how an untested host would execute the text.
3. A YAML list for `allowed-tools`. Generic validation accepted it even though the
   standard describes a space-separated string. Host-specific accepted syntax
   needs to be separated from the portable representation.

The probes were only audited; their embedded example commands were never run.
See `probes` in the evidence JSON for exact observed outcomes.

## Prioritized improvements

All six items are **proposed**, first and last reviewed October 22. Detailed
acceptance criteria and risks are maintained in the
[cumulative opportunity ledger](opportunities.md).

| ID | Priority | Recommendation | Expected benefit | Effort |
| --- | --- | --- | --- | --- |
| OPT-001 | P1 | Enforce target-aware metadata constraints | Catch unusable packages before distribution | Small–medium |
| OPT-002 | P1 | Separate field preservation, preapproval, and restrictive tool policy | Avoid overstating cross-host semantic support | Medium |
| OPT-003 | P1 | Diagnose host-specific body syntax during audit/compile | Expose behavior changes hidden by byte preservation | Medium |
| OPT-004 | P2 | Expand scenario coverage and add opt-in versioned runtime evidence | Make trigger, lifecycle, fidelity, and efficiency claims measurable | Large |
| OPT-005 | P2 | Review recipes for checklist and clarify | Reduce context only where conditional loading preserves behavior | Medium |
| OPT-006 | P3 | Add catalog-level discovery diagnostics | Detect trigger descriptions lost to listing budgets | Medium |

Start with OPT-001 through OPT-003, using the demonstrated probes as regression
cases. Build the evaluation design in OPT-004 before treating OPT-005 as a
validated efficiency improvement. Do not infer target permission enforcement
from preservation of a frontmatter field.

## Reproduction

Run from the repository root, using a fresh temporary output directory:

```bash
python3 --version
python3 -m harnessmith --version
python3 -m unittest discover -s tests -v
python3 scripts/check_repository.py all
python3 scripts/check_repository.py docs
python3 -m harnessmith skills/speckit-analyze \
  --recipe recipes/speckit-analyze.cursor.json \
  --output /tmp/harnessmith-review-2026-10-22/compiled --json
python3 -m harnessmith verify /tmp/harnessmith-review-2026-10-22/compiled --json
python3 -m harnessmith verify examples/compiled/cursor/speckit-analyze --json
```

The audit matrix calls `harnessmith.audit.audit_skill(path, target)` for each
`skills/*/SKILL.md` and `harnessmith.targets.TARGET_NAMES` entry. The offline
matrix calls `evaluate_scenario(load_scenario(path), repository_root=Path.cwd())`
for every `evaluations/scenarios/*.json`. Full results are retained in the
evidence JSON, so future comparisons do not depend on temporary files surviving.
