# Workflow v4 repairs and proposed diagnostic pilot

Status: **offline candidate only; no live sessions authorized or launched**.
The completed [v3 pilot](workflow-fidelity-v3-results.md) retains 1/2 frozen
automated passes and 0/2 complete reviewed passes. All earlier reports, grades,
packages, instruments and original skill bytes remain frozen. OPT-004 remains
incomplete and no router is promoted or installed.

## Repair scope

The new [router v4](../evaluations/variants/speckit-checklist-router-v4/SKILL.md)
and [review record](../evaluations/variants/speckit-checklist-router-v4.review.json)
change only the shared root and project-generation reference. Discovery metadata
and both example references are byte-identical to v3. The full post-hook
procedure now occupies the numbered action checkpoint immediately before
reporting, replacing the distant procedure and pointer. It requires actual
completed Markdown blocks at the left margin before invoking automatic hooks.

The router also inventories the known-existing feature directory before creating
a checklist directory, asks neutrally about unspecified policy, and ties report
claims to returned file bytes, completed messages or tool results. Missing
metadata or an untried tool cannot establish an unavailable capability. These
are authored instruction changes, not evidence of model compliance or a proven
content-preserving compiler transformation.

Checker and collector v4 use
[rubric v5](../evaluations/variants/router-quality-rubric-v5.md). The checker
recognizes bounded invitation reuse paraphrases and records the lexical cues
supporting its topic allocation. It also screens a limited grammar of affirmative
final hook claims against timely offers and successful invocations. No recognized
claim or a screen pass never establishes general narrative accuracy. Semantic
policy neutrality and the accuracy of environmental claims remain mandatory
manual review.

The trace normalizer remains v3, pinned along with inherited checker helpers.
Observation schema stays v3; new checker/collector report identities are v4.
There is no broader shell support or relaxation for failed discovery, denied
writes or unsupported operations. The compiler's leave-inline default is unchanged.

Both cases retain all existing ID/count, template, question/quality/traceability,
Gap, constitution, reference order, preservation, setup, phase timing and
permission checks. Every applicable hard check and semantic/raw review must

needs a different initial artifact state. These are the smallest unchanged cases
covering the observed repair targets.

a heuristic scope estimate, not a token, price or spending cap. Caching and
instruction changes can move usage outside it. Record total/cached/uncached
input, output and latency separately; no efficiency comparison is proposed.

## Offline validation and preservation

The [config](../evaluations/workflow-fidelity-v4/pilot.json) and
[preparation guide](../evaluations/workflow-fidelity-v4/README.md) create two
isolated workspaces without credentials, model calls or attempts. Tests cover
bounded topic cues and distractors, actual versus promised or quoted hook blocks,
unsupported hook assertions, immutable inputs, package tampering, fake collection,
fixed session count, retention and stop/no-retry behavior. Synthetic controls
validate instruments and package contracts, not live instruction compliance.

Validation on 2026-10-25: **373 repository tests passed; 84% coverage**. The 31
new tests comprise 17 checker tests, eight package tests, five fake-server
collector tests and one local discovery test covering absent, empty and populated
checklist directories. Ruff, mypy (43 source files), repository schemas and
documentation, and `git diff --check` pass. The final complete suite includes
quote/negation fixes found during separate read-only design review; the earlier
complete 373-test log is also retained.

The new checks preserve affirmative versus negative/quoted/future claim
boundaries without pretending to parse arbitrary narration. Controls confirm
that a topic screen can pass a policy-presupposing question while its semantic
review remains pending. Actual local `rg` discovery runs against temporary
synthetic directories and is accepted by the unchanged v3 parser; this is not
a future-host sandbox guarantee. Fake-server tests retain failures without
retries and stop on instrumentation defects before consuming the second slot.
