# Codex runtime evidence

The first Codex adapter is an opt-in, single-turn **explicit invocation probe**.
It uses the [Codex App Server](https://learn.chatgpt.com/docs/app-server)
stdio protocol. It does not yet verify implicit invocation, non-triggers,
approvals, continuation, compaction, hooks, or abort. Those scenarios fail
preflight instead of substituting descriptive prompts for real events.

## Run locally

Sign in with the Codex CLI first. Select a model available to that account and
replace `MODEL_ID` below. The output directory must not exist.

```bash
python3 -m harnessmith.codex_runtime \
  evaluations/scenarios/runtime-probe-codex.json \
  --model MODEL_ID \
  --samples 3 \
  --timeout 120 \
  --output /tmp/harnessmith-codex-evidence \
  --enabled
```

This makes six real sessions (three canonical/compiled pairs) and consumes model
usage. `--timeout` bounds each session; it is not a monetary spending limit.
`--codex` selects an executable and `--auth-file` selects an existing local
`auth.json`. Without `--enabled`, no server is started. Ordinary CI only runs
fake-server and scoring tests and never authenticates or contacts a model.

The probe asks for a label's code held in the skill's Lookup section. The
compiler extracts that section into `references/lookup.md`. The prompt does not
contain the answer or the expected trace. The canonical variant can answer from
its root instructions; the compiled variant must load the reference.

## Isolation and measurement

Each sample starts a separate stdio server, ephemeral thread, temporary workspace,
and temporary Codex home. Only the selected skill package is installed. Existing
local authentication is copied with owner-only permissions to that temporary
home and deleted with the temporary directory. User configuration is not copied.
Other discovered skills are disabled for the thread. Managed host policies can
still apply; this is not an operating-system container.

Both variants use the same explicit skill input mechanism, read-only sandbox,
`never` approval policy, disabled web search, and low reasoning effort. The shell
inherits no environment variables and receives a fixed system-tool PATH
(`/usr/bin:/bin:/usr/sbin:/sbin`). Unexpected
server requests stop collection. No approval is automatically granted. The
adapter records the CLI version and requested model identifier; the provider's
underlying model snapshot is explicitly marked unreported. Fresh sessions do not
mean cold provider caches. Raw token-usage events retain cache-related fields
when supplied, while the report uses cumulative input/output totals once.

Latency covers initialization through turn completion, including skill discovery;
it is session latency, not pure inference time. Raw logs retain thread-start
responses and observed permissions. The collector's static estimates remain
separate from runtime usage.

## Scoring and artifacts

- `report.json` contains completed paired evidence, including failed checks.
- `raw/*.jsonl` retains sent requests and received protocol messages; filenames
  are the first 24 hexadecimal characters of SHA-256 of the collector session ID.
- `raw/*.stderr` retains server diagnostics.
- `incomplete.json` records collection errors. No completed report is emitted for
  a timeout, malformed measurements, protocol failure, or failed model turn.

Explicit invocation is established by an accepted skill input item and a
completed turn; it does not prove automatic skill selection. Reference reads
come from successful `commandExecution` items classified as `read` by Codex,
resolved against the actual package directory. A model saying it read a file
is not a read event. This relies on Codex's command classifier, not OS file-access
tracing. Failed or unclassified commands and other tool items remain unexpected
actions and fail the probe. The output check uses the scenario's deterministic
substring contract, not a semantic judge.

Exit codes are `0` for passing completed evidence, `1` for completed evidence
with fidelity failures, and `2` for invalid configuration or incomplete evidence.
Keep raw logs private: they include prompts, outputs, local paths and diagnostics.
The adapter does not publish or upload the evidence bundle.

## Current verification status

The implementation was checked against the protocol schema generated by local
`codex-cli 0.163.0-alpha.11`. Offline tests exercise the real adapter through a
fake stdio process, including paired collection and reference-read scoring.
They are labeled mock evidence. On October 23, 2026, an authorized live run
completed two canonical/compiled pairs using gpt-6-astra. All four returned the
expected code, but all four failed fidelity checks: instrumentation v1 removed
PATH, causing failed `cat` commands and `/bin/cat` retries classified as unknown.
The compiled reference reads therefore did not satisfy the scorer. Responses also
included commentary; the substring output contract does not enforce code-only
answers. The report passed the published evidence schema.

Instrumentation v2 adds a fixed system-tool PATH. A second authorized run on
October 23, 2026 completed two pairs with all 24 current checks passing. Both
compiled runs had classified, successful lookup-reference reads, with no failed
command retries. Canonical sessions averaged 23,074 input tokens and 8.254 seconds;
compiled sessions averaged 34,989.5 input tokens and 11.565 seconds. The tiny probe
adds a reference-read round trip and demonstrates no efficiency benefit. These
two-pair measurements include harness overhead and uncontrolled provider caching;
they do not establish broader performance behavior. The substring-contract
limitation above still applies.

Both original evidence bundles, raw traces and adapter source snapshots are
retained under the git-ignored `evaluations/local-evidence/` directory. The second
report also passed the published evidence schema. This verifies the current
explicit probe, not the wider OPT-004 acceptance matrix.

This is the first executable slice of OPT-004, not completion of its wider
fidelity matrix. Subsequent recipe-backed consultation comparisons are linked
from [the current acceptance map](opt-004-status.md). Real implicit invocation
and lifecycle events remain unverified. The next proposed work is the
[isolated workflow pilot](workflow-fidelity-pilot.md); this read-only adapter
cannot collect its artifact writes or hook execution.
